However, using `.pipe()` in production applications is not recommended for several reasons. If one of the piped streams is closed or throws an error, `pipe()` will not automatically destroy the connected streams. This can cause memory leaks in applications. Also, `pipe()` does not automatically forward errors across streams to be handled in one place.

`pipeline()` was introduced to cater for these problems, so it's recommended you use `pipeline()` instead of `pipe()` to connect multiple streams. We can rewrite the above `pipe()` example to use the `pipeline()` function

```
inputStream.pipe(hashStream).pipe(outputStream);
pipeline(inputStream, hashStream, outputStream, (err) => {
  err && console.error(err);
});
```

`pipeline()` accepts a callback function as the last parameter. Any forwarded errors from any of the piped streams will call the callback, so it's easier to handle errors for all streams in one place.

花了不少时间研究 一个 nginx 配置 两套 php 代码方法，有几个心得：

1. 网上可查情况多少一个 nginx 对应两套独立的 php 代码 (尤其要注意 laravel 项目只有一个 `index.php` 入口)，通过不同`location`模块设置不同应用，注意是设置不同的 `fastcgi_pass`. 两套独立php代码放置在不同目录，location做相应设置，[how to put your PHP application in a subdirectory of another site](https://serversforhackers.com/c/nginx-php-in-subdirectory) 另我们自己代码没有用location嵌套的方式。

### redis database

#### pub sub

[Is there a way to fully separate two redis databases for pub/sub usage?](https://stackoverflow.com/questions/45737357/is-there-a-way-to-fully-separate-two-redis-databases-for-pub-sub-usage) "No PubSub is shared across all clients connected to the server, regardless of their currently `SELECT`ed database"

#### 合适使用多database情况

[What's the Point of Multiple Redis Databases?](https://stackoverflow.com/questions/16221563/whats-the-point-of-multiple-redis-databases) 大多不建议使用多database，而是 ”Let the access pattern determine how to structure your data rather than store it “， 可能合适使用情况包括：

1. 管理相对方便 There's one clear advantage of using redis databases in the same redis instance, and that's management. 
2. 使用云端服务省钱的方法 If you use a "cloud Redis" from your favourite cloud provider, you probably have a minimum memory size and will pay for what you allocate. If however your dataset is smaller than that, then you'll be wasting a bit of the allocation, and so wasting a bit of money.
3. 有人提到开发、测试、生产部署用同一个redis，不同数据库，这个未必合适 Different copies of the same database could be used for production, development or testing using real-time data. People may use replica to clone a redis instance to achieve the same purpose. However, the former approach is easier for existing running programs to just select the right database to switch to the intended mode.

总之我们要仔细确认使用多database 情况。CR目前使用方式是错误，因为他们对redis不够了解。

[Why using multiple database in same instance a bad idea in Redis?](https://stackoverflow.com/questions/43244958/why-using-multiple-database-in-same-instance-a-bad-idea-in-redis) 不好在于redis单线程，多个database 不如多起一个实例；redis cluster不支持多数据库。

#### 脏数据

目前在开发环境 `websocket:socket_user` 包含很多无效数据，曾经连到实际生产环境看它的无效数据倒不多。推测原因docker容器重启，或者网络原因，没有收到`disconnect` 消息，所以没能及时删除  `websocket:socket_user` 记录。

我们最早实现曾经在应用重启时候**清空**redis记录来避免脏数据。但实际运行又发现k8s有时候只重启一个容器，所以清空所有记录就不可行。目前考虑解决办法是引入 `node-cron` 每天起一个定时任务清理无效数据；暂不考虑在程序启动时候清理无效数据，因为不知道实际清理需要的执行时间，虽然预计很短。

另，目前有python的清理脚本，js实现也很简单

#### 缺乏统计数据

目前没有手段知道峰值ws连接数， `websocket:socket_user` 包含很多无效数据，所以用 `hlen websocket:socket_user` 来查当前连接数就不准。后来引入 `"@socket.io/admin-ui"`就是为了解决这个问题，但是目前现网v5不包含这个改动。要尽快把这个改动引入现网，其他哪些统计数据有用还需要考察。

是不是每次调用 `asyncLocalStorage.getStore()` 如何能取到自己的context, `asyncLocalStorage.run(cnt)` Node.js 文档写 Each instance of `AsyncLocalStorage` maintains an independent storage context. Multiple instances can safely exist simultaneously without risk of interfering with each other's data.

详见文档

`asyncLocalStorage.run(store, callback[, ...args])` Runs a function synchronously within a context and returns its return value. The store is not accessible outside of the callback function. The store is accessible to any asynchronous operations created within the callback.

`asyncLocalStorage.getStore()` Returns the current store. If called outside of an asynchronous context initialized by calling `asyncLocalStorage.run()` or `asyncLocalStorage.enterWith()`, it returns `undefined`.
