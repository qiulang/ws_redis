[Use Streams to Build High-Performing Node.js Applications](https://blog.appsignal.com/2022/02/02/use-streams-to-build-high-performing-nodejs-applications.html) 这是 2022的文章，提到这点是我们没做到的，

However, using `.pipe()` in production applications is not recommended for several reasons. If one of the piped streams is closed or throws an error, `pipe()` will not automatically destroy the connected streams. This can cause memory leaks in applications. Also, `pipe()` does not automatically forward errors across streams to be handled in one place.

`pipeline()` was introduced to cater for these problems, so it's recommended you use `pipeline()` instead of `pipe()` to connect multiple streams. We can rewrite the above `pipe()` example to use the `pipeline()` function

```
inputStream.pipe(hashStream).pipe(outputStream);
pipeline(inputStream, hashStream, outputStream, (err) => {
  err && console.error(err);
});
```

`pipeline()` accepts a callback function as the last parameter. Any forwarded errors from any of the piped streams will call the callback, so it's easier to handle errors for all streams in one place.

### nginx config

花了不少时间研究 一个 nginx 配置 两套 php 代码方法，有几个心得：

1. 网上可查情况多少一个 nginx 对应两套独立的 php 代码 (尤其要注意 laravel 项目只有一个 `index.php` 入口)，通过不同`location`模块设置不同应用，注意是设置不同的 `fastcgi_pass`. 两套独立php代码放置在不同目录，location做相应设置，[how to put your PHP application in a subdirectory of another site](https://serversforhackers.com/c/nginx-php-in-subdirectory) 另我们自己代码没有用location嵌套的方式。
2. 我们是同一套代码，对于特定路由转发到它对应的独立容器，所以是通过不同`location`模块设置不同的[ `proxy_pass`](https://docs.nginx.com/nginx/admin-guide/web-server/reverse-proxy/) ，目前v6前端镜像转发工单知识库处理就是这样。
3. Nginx’s FastCGI proxying  文章很多，参见 https://www.digitalocean.com/community/tutorials/understanding-and-implementing-fastcgi-proxying-in-nginx
4. [Nginx: Everything about proxy_pass](https://dev.to/danielkun/nginx-everything-about-proxypass-2ona) 没再细看

我们gitlab 服务器配置https到标准端口，不需要动 gitlab自带的nginx配置，只要修改 `/etc/gitlab/gitlab.rb` 详见 11.2日报
